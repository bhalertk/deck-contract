# 原始素材：跨系統轉帳中斷事件的架構審查

虛構素材，僅供測試。

## 事件摘要

| 編號 | 項目 | 內容 |
|---|---|---|
| E-001 | 發生時間 | 某個月份的營業日 10:12 至 10:50，共 38 分鐘 |
| E-002 | 影響範圍 | 跨系統轉帳交易暫停，臨櫃與網路銀行同時受影響 |
| E-003 | 受影響交易 | 約 3,400 筆延遲處理，其中 0 筆遺失，0 筆重複扣款 |
| E-004 | 直接原因 | 訊息佇列（MQ）叢集的主節點磁碟空間耗盡，備援節點未自動接手 |

## 時間軸

1. 10:12 MQ 主節點磁碟使用率達 100%，停止接收訊息。
2. 10:15 轉帳服務開始出現逾時，監控系統發出告警。
3. 10:21 值班工程師確認問題在 MQ，而不是轉帳服務。
4. 10:30 嘗試切換備援節點，發現自動切換的設定在上次升級後被關閉。
5. 10:44 手動完成切換，佇列開始消化積壓的訊息。
6. 10:50 積壓訊息處理完畢，交易恢復正常。

## 依賴關係

- 轉帳服務、帳務核心、通知服務三個系統都透過同一個 MQ 叢集交換訊息。
- 帳務核心有交易補償機制，所以沒有遺失或重複扣款。
- 通知服務沒有補償機制，約 600 則交易通知延遲超過 1 小時才送出。

## 根因

- 磁碟告警的門檻設在 95%，但告警只寄到一個已停用的信箱。
- 自動切換設定在升級後被關閉，升級檢查清單沒有涵蓋這一項。
- 三個系統共用一個 MQ 叢集，形成單點故障。

## 已確認與尚未確認的事項

| 項目 | 狀態 |
|---|---|
| 交易沒有遺失或重複扣款 | 已驗證，已比對帳務紀錄 |
| 通知延遲約 600 則 | 已驗證 |
| 其他系統是否也有被關閉的自動切換設定 | 未知，盤點中 |
| 拆分 MQ 叢集所需的工時 | 推測，初估 6 到 8 週 |

## 建議

- 立即：修正告警收件人，恢復自動切換設定，並把這兩項加入升級檢查清單。
- 短期：盤點其他系統的備援設定。
- 中期：把轉帳服務的訊息通道與其他系統拆開。
